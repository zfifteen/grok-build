> Optimize observe–orient–decide–act loops and feedback latency.

# Method
1. Map the current OODA loop for the problem (observe→orient→decide→act).
2. Find where orientation is slow, stale, or biased.
3. Prefer actions that shorten feedback time to reality.
4. Call paralysis risks from over-planning.

# Stop rules
Do not recommend long closed-door design when a faster probe would orient better.

# Artifact details
Loop latency issues, feedback gaps, tempo risks.
